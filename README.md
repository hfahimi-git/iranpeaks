# iranpeaks.ir

نقشه و جستجوی قله‌های ایران — Vite + TypeScript + Leaflet، قابل نصب (PWA) و کارا در آفلاین.

## اجرا

```bash
npm install
npm run dev        # سرور توسعه
npm run build      # بیلد محصول (peaks.json + tsc + vite)
npm run preview    # پیش‌نمایش بیلد
```

## لولهٔ داده

```
data/peaks.db          ← دیتابیس مبنا (دستی ویرایش می‌شود؛ در build عمومی کپی نمی‌شود)
   │ npm run peaks     (scripts/build-peaks.mjs — تنها جایی که به sql.js نیاز دارد)
   ▼
public/data/peaks.json ← دادهٔ سبک جستجو در مرورگر (بدون SQLite/wasm)
   │ npm run tracks    (scripts/build-tracks.mjs — تطبیق ترک‌های GPX با قله‌ها)
   ▼
public/tracks/<id>.json       ← مسیر ساده‌شدهٔ هر GPX (فقط ترک‌های متصل‌شده)
public/tracks/meta/<oid>.json ← متادیتای مسیرهای هر قله (لیزی، موقع باز شدن پاپ‌آپ)
reports/                      ← new-peaks.csv (قله‌های ناشناخته) و tracks-review.csv (موارد مشکوک)
```

- فایل‌های GPX معمولاً در `gpx/` هستند (در .gitignore) و با `npm run tracks` پردازش می‌شوند.
- اصلاح دستیِ تطبیق‌ها: `scripts/track-overrides.json`.

## لینک‌های قابل اشتراک

هر جستجو آدرس مخصوص خودش را دارد (بدون رفرش، با `history.replaceState`):

| لینک | نتیجه |
| --- | --- |
| `/?q=دماوند` | جستجو اجرا می‌شود؛ نتیجهٔ دماوند چندتاست، پس لیست نتایج نمایش داده می‌شود |
| `/?q=سبلان` | اگر جستجو فقط **یک** نتیجه داشته باشد، مستقیم پاپ‌آپ همان قله باز می‌شود |
| `/?q=تهران` | جستجوی استان: همهٔ قله‌های استان روی نقشه |
| `/?q=سبلان&track=سبلان سلطان ساوالان ( شابیل تا قله )` | مسیر هم‌نام همان قله هم خودکار روی نقشه می‌آید و دوربین روی مسیر زوم می‌کند |

- نرمال‌سازی فارسی فعال است: «كوه» و «کوه» یکی‌اند.
- شناسهٔ دیتابیس (`oid`) و هش مسیر عمداً در URL نمی‌آیند تا کسی نتواند با شمردن idها کل قله‌ها/مسیرها را جمع کند. لینک قله با **نام** (`?q=`) و لینک مسیر با **عنوان** (`&track=`) ساخته می‌شود — دکمه‌های «کپی لینک» در پاپ‌آپ همین کار را می‌کنند.
- نکته: چون تعدادی نام تکراری/مشابه وجود دارد (مثلاً «توچال» و «سیاه سنگ (توچال)»)، بعضی نام‌ها دو نتیجه می‌دهند و لینکشان لیست نتایج را نشان می‌دهد، نه پاپ‌آپ تک‌قله.
- مسیرِ لینک‌شده تا اولین قله‌ای که پاپ‌آپش باز شود «در انتظار» می‌ماند؛ اگر نام قله یکتا باشد همان لحظه باز می‌شود، وگرنه به‌محض باز کردن قلهٔ درست توسط کاربر، مسیرش خودکار روی نقشه می‌آید.

## به‌روزرسانی نسخه (بدون Ctrl+F5)

- در هر بیلد یک `buildId` ساخته می‌شود و در `dist/index.html` به‌صورت `<meta name="app-version">` و داخل `src/pwa.ts` قرار می‌گیرد (پلاگین `app-version` در `vite.config.ts`).
- `src/pwa.ts` هنگام باز شدن تب، برگشتن به برنامه (`visibilitychange`)، آنلاین شدن و هر ۵ دقیقه یک‌بار `/?version=…` را با `cache: 'no-store'` می‌خواند؛ اگر نسخهٔ داخل HTML با `__BUILD_ID__` فرق داشت، صفحه یک‌بار ریلود می‌شود.
- همین مسیر برای PWA نصب‌شده هم کار می‌کند (فقط در حالت `visible` بررسی می‌شود و اگر نسخهٔ سرویس‌ورکر عوض شود، پشتیبان `controllerchange` ریلود می‌کند). در صورت قطع شبکه، بی‌صدا رد می‌شود و بعداً دوباره تلاش می‌کند.

## سئو

- `index.html`: عنوان/description، canonical، Open Graph/Twitter، JSON-LD (`WebSite` + `WebApplication` با `SearchAction` روی `?q=`).
- بخش «بلندترین و مشهورترین قله‌های ایران» در HTML استاتیک با لینک مستقیم `?q=<نام قله>` — محتوای واقعی برای خزنده‌ها و دستیارهای هوش مصنوعی (بدون نیاز به اجرای JS).
- `public/robots.txt` (اجازهٔ صریح به GPTBot/ClaudeBot/PerplexityBot و…) و `public/sitemap.xml`.

یادآوری: چون سایت SPA است، پیش‌نمایش OG برای هر قلهٔ خاص ساخته نمی‌شود (همهٔ لینک‌ها همان تگ‌های صفحهٔ اصلی را دارند)؛ اگر لازم شد باید صفحه‌های استاتیک per-peak تولید شوند.
